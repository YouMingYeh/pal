# Pal database spike

Apply every migration in filename order to a dedicated Supabase project. They define the group chat, RLS, atomic job queue, reminder delivery, replay handling, and explicit grants. The Cron migration enables `pg_cron` and delivers due reminders once per minute. Enable Email Auth; the application signs in with real Supabase sessions.

Authenticated clients can read only their groups' rows. Clients write through `create_group(p_name)`, `join_group(p_invite_code)`, and `send_message(p_group_id,p_body,p_client_id)`. Invite codes are UUID bearer invitations; share them only with intended members. Reusing a message client ID is idempotent and changing its body is rejected. An explicit `@Pal` mention inserts an agent job in the same transaction as the message.

The server uses its secret key to call `claim_agent_jobs(p_limit)`, `complete_agent_job(p_job_id,p_attempt,p_body,p_result)`, and `fail_agent_job(p_job_id,p_attempt,p_error)`. Claiming leases a job for five minutes and increments its attempt. Completion checks the attempt, posts one Pal message, and completes the job atomically. Failed jobs retry up to three attempts; expired leases are recoverable. Store the Eve session ID in `agent_jobs.result` as serialized JSON. Only clear it after a terminal Eve failure; a disconnected worker should resume the existing session.

After deploying the API, store its full HTTPS `/api/dispatch` URL in Supabase Vault as `pal_dispatch_url` and the server's `CRON_SECRET` as `pal_cron_secret`. Then apply `agent-recovery.sql` to schedule a minute-by-minute authenticated HTTP dispatch. It references Vault at execution time so the bearer token is absent from migration files and the Cron job's SQL. Do not select decrypted Vault values in logs. Supabase's `net._http_response` records HTTP status; check it together with `cron.job_run_details` to verify requests reached the API.

The server's scoped reminder tool calls `create_reminder(p_group_id,p_requester_id,p_body,p_due_at,p_timezone,p_source_key)`. It checks actual membership, future time, IANA timezone, and a stable idempotency key. `private.deliver_due_reminders()` locks up to 100 due rows, posts one message per reminder, and marks them completed in the same transaction. It runs entirely in Postgres while clients and the API server are offline. A reminder appears in chat on reconnect; APNs notification delivery is a separate integration.

`tests/spike.sql` is an assertion suite for a **dedicated, empty test database**. It creates three Auth fixtures in a transaction and rolls back. It checks allow/deny access, message/job/reminder deduplication, worker leases, stale completion, and reminder cancellation/delivery. Run using `psql "$PAL_TEST_DATABASE_URL" -v ON_ERROR_STOP=1 -f supabase/tests/spike.sql` after applying every migration. Supabase's direct default grants to client roles are explicitly revoked by the grant-hardening migration; revoking `PUBLIC` alone is insufficient. Live Cron must also be checked by creating a future reminder, disconnecting clients, and verifying its message after the next minute.

Do not expose a Supabase secret or service-role key in the iOS app. Group membership must also be checked by every privileged backend route because the server key bypasses RLS.
