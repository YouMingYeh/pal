# Pal v1 flow review

The app opens in the chat list under the centered Pal title. Group content lives in the conversation, Map and Calendar; account connections live in Profile. Chat is plain text with short paragraphs and inline emphasis. Pal helps through conversation; polls and message cards are hidden.

This review covers the approved stories and their recovery paths. Live checks use real accounts/providers; SQL and native tests cover deterministic behavior. It does not imply every gesture was manually exercised on every iOS version.

| Story | Flow and friction removed | Verification |
|---|---|---|
| Sign in and identity | Apple sign-in; a focused editor with a large avatar, Camera/Photo Library menu, editable name and one Save action. Avatar files stay private and are shared through temporary links with group members. | Physical sign-in/group join; real hosted image upload, metadata removal, member reads, access denial and removal cleanup. |
| Create, invite and join | Name and optional group photo, then Create. Invite with a QR code or link; joining resumes after sign-in. Pasted invites remain a fallback. | Hosted atomic creation/photo/idempotency and access checks; native QR decoding and physical scanning are separate checks. |
| Find a chat | Centered Pal title, profile and new-chat controls; name, latest message and unread count, without row dividers. | Hosted two-member smoke and SQL; native render. |
| Launch | Centered cloud artwork on the native launch screen, then a short fade while normal loading proceeds. Reduce Motion skips the transition. | Signed build and physical launch; simulator tests. |
| Private Pal chat | Pal is pinned above groups. Ask naturally about recent discussion across current memberships, without invite, Map or Calendar controls. Cross-group reads never write to source groups. | Nullable-invite/legacy model regression and native build; service permission and context-budget tests. |
| Conversation | Adaptive monochrome bubbles and toolbar controls, with orange action accents; grouped sender labels with 32pt member photos and Pal avatars, with larger names and message text; date/time separators, without a timestamp on each bubble. Individual glass controls float above a soft scroll edge. | Native render/tests. |
| Pal expression and movement | Each reply retains its tone and animates while visible, including history. The supplied demo's emotion-specific motion accompanies the animated eye/body frames. Offscreen/background views and Reduce Motion stop playback. | Persisted real Eve `triste`, SQL tone/lease/access assertions, and native rendered-window tests. The mounted-window regression caught the visibility gate that asset-only checks missed; source resolution is checked against native display density. The selected physical iPhone test confirms exact image bounds and changing rendered pixels; the UIKit intrinsic-size overflow was reproduced before repair. |
| Pal activity | Sending immediately shows an animated Pal is typing status in a reserved composer lane. Actual accepted/running server work sustains it; silent completion, failure, pause and expiry stop it. Pal still chooses when to reply. | Native stale-state and fixed-height tests at normal/accessibility text sizes; hosted future-debounced accepted state and actual silent completion; SQL activity/privacy assertions. |
| Reply and react | Native long-press reaction palette, Reply and Copy. Text URLs are tappable. | Native render and hosted reply/reaction assertions. |
| First entry and realtime | Unknown history stays quietly loading; only an authoritative empty snapshot shows No messages yet. The inbox prefetches at most two histories at once. Reopened chats reuse account-scoped memory; authenticated Realtime triggers fresh authorized reads, with polling recovery. | Native unknown/empty, stale snapshot, logout/prune and actual WebSocket tests; hosted three-client member/outsider CDC verification. |
| Failed delivery | No sending indicator. Accepted responses enter the cache before the outbox clears; stable client identity keeps one bubble through delivery. Failed text/media retain the original reply and file for retry. | Hosted idempotency and native stale-snapshot/outbox tests; the user confirmed the bubble no longer disappears. |
| Photos and audio | Plus opens Photos, Camera or Audio; review/remove a draft before sending. Private signed media is shared with group members. | Hosted and native actual JPEG/AVFoundation AAC uploads/downloads, exact retry, replies, invalid-file rejection and outsider access denial. Uppercase iOS UUID URLs are exercised. Hardware camera/microphone checks remain manual. |
| Share a reel | Share extension selects a group and submits through the authenticated message API; pasting uses the same ingestion. | Extension builds/session tests; pasted real reel live. System share gesture remains a manual check. |
| Inspect a place | Pal describes results in text with the original link. Resolved places appear in Map; uncertain branches require a conversational correction. | Real supplied reel: Tur, five dishes and timestamp evidence; Apple Maps match. |
| Unclear/inaccessible source | Pal asks a focused question or preserves the link with a short failure explanation. Members can correct the place in Map details. | Schema/security tests and correction flow review. Private-video provider behavior varies. |
| Multiple places | Pal lists useful candidates in text; validated resolved records appear on the group map. | Validated multi-candidate extraction and saved-place records; actual multi-place video remains a manual provider check. |
| Collection and duplicates | Search saved places or push Map onto the chat navigation stack. One place keeps source contributors. | Hosted dedup, SQL and native state/render. |
| Preferences and context | Pal quietly reads group history and remembers explicit statements about the speaker. Members correct it through chat; no memory editor. | Real Eve ordinary-message preference capture with exact speaker/source and zero unsolicited reply; SQL ownership assertions. |
| Availability | Members state their times naturally. Pal remembers exact speaker/source and applicable dates; dated availability expires, unanswered remains unknown. | Source-grounded capture and expiry assertions. There are no time-slot polls in the demo. |
| Choose a place | Pal offers a short shortlist and members answer in chat. Anything works is a preference, never attendance. | Real ordinary-message capture previously verified this distinction; no new poll creation tool is exposed. |
| Confirm and RSVP | An explicit member message can confirm a current future draft; attendance is a separate own Yes/Maybe/No statement. Calendar details provide native member actions where needed. | Conservative intent tests and SQL current-version/source/lease/idempotency assertions; real member RSVP and Google sync verified. |
| Reserve | Research verifies a booking link; a member opens it and records a completed booking. Drafts do not imply booked tables. | Real official booking-page verification plus scoped-tool tests. No reservation submitted. |
| Group calendar | Push Calendar, choose a date, review agenda/upcoming/past plans; native back and swipe-back. | Native calendar render/model tests; gesture remains a device check. |
| Google Calendar | Connect once; create a separate Pal calendar; sync only confirmed plans where that member said Yes. | Real consent, exactly one live Google event, and an edited plan updating the same copy despite retries. |
| Apple Calendar | Open Apple's native editor, review and save a manual copy. Pal does not read personal events. | Native editor/date/receipt checks; physical save requires a member action. |
| Follow-ups | Responded members are excluded; remaining reminders stop once resolved. Quiet hours apply to nonurgent pushes. | SQL recipient/deadline assertions. |
| Attendance reminders | Server schedules future 24h/2h reminders for Yes attendees; pushes open the relevant record. | SQL lifecycle plus a physical closed-app reminder/tap check. |
| Changes and cancellation | Persisted plan details update; material time changes clear RSVPs and replace reminders/calendar copies. Chat describes the result in text. | Hosted lifecycle assertions and real Google edit/retry/cancellation cleanup. |
| Direct reminder | Ask Pal in chat; Pal confirms the saved purpose and local time in text. Scheduling persists on the server. | Hosted server reminder and physical closed-app APNs/tap verification. |
| Notification control | Explicit Enable requests iOS permission. Background registration failures appear quietly in Profile and do not interrupt navigation; successful registrations are deduplicated within the signed-in session. | Physical permission, device registration and APNs delivery; native failure-presentation checks. |
| Demo scenarios | Three fictional rooms and eight photo profiles include preferences, places, drafts and distinct Pal tones. Old visible history is backed up privately before reset; actual login/profile/device/Calendar connections remain. | Reviewed manifest, real venue resolution, guarded seed and private completion receipt. Mock dialogue never implies an actual reservation. |
| Group details | Members and invitations only; agent settings and manual memory/poll creation are hidden. | Native flow review; existing backend guards remain in place. |
| Accessibility | Native text/controls, meaningful action labels, Dynamic Type layouts, light/dark mode and Reduce Transparency fallback. | Native accessible dark rendering and builds. VoiceOver narration and iOS 26 glass on hardware remain manual checks. |

Deferred features remain location sharing, automatic booking, two-way calendar sync, games, image generation and a personal feed. Google's test-mode OAuth warning is expected; its refresh credentials can expire after seven days. The installed Debug app uses sandbox APNs; TestFlight needs production APNs credentials.
