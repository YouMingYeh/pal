# Pal v1 flow review

The app opens in the chat list under the centered Pal title. Group content lives in the conversation and Calendar; account connections live in Profile. The Map toolbar entry is removed. Chat uses short paragraphs and inline emphasis. Pal helps through conversation and compact persisted cards: plans, inspiration options, group availability, and focused questions. Manual poll creation stays hidden.

This review covers the approved stories and their recovery paths. Live checks use real accounts/providers; SQL and native tests cover deterministic behavior. It does not imply every gesture was manually exercised on every iOS version.

| Story | Flow and friction removed | Verification |
|---|---|---|
| Sign in and identity | Apple sign-in; a focused editor with a large avatar, Camera/Photo Library menu, editable name and one Save action. Avatar files stay private and are shared through temporary links with group members. | Physical sign-in/group join; real hosted image upload, metadata removal, member reads, access denial and removal cleanup. |
| Create, invite and join | Name and optional group photo, then Create. Invite with a QR code or link; joining resumes after sign-in. Pasted invites remain a fallback. | Hosted atomic creation/photo/idempotency and access checks; native QR decoding and physical scanning are separate checks. |
| Find a chat | Centered Pal title, profile and new-chat controls; name, latest message and unread count, without row dividers. | Hosted two-member smoke and SQL; native render. |
| Launch | Centered cloud artwork on the native launch screen, then a short fade while normal loading proceeds. Reduce Motion skips the transition. | Signed build and physical launch; simulator tests. |
| Private Pal chat | Pal is pinned above groups. Ask naturally about recent discussion across current memberships, without invite or Calendar controls. Cross-group reads never write to source groups. | Nullable-invite/legacy model regression and native build; service permission and context-budget tests. |
| Conversation | Adaptive monochrome bubbles and toolbar controls, with orange action accents; grouped sender labels with 36pt member photos and Pal avatars, with larger names and message text; date/time separators, without a timestamp on each bubble. Individual glass controls float above a soft scroll edge. | Native render/tests. |
| Pal expression and movement | Each reply retains its tone and animates while visible, including history. The supplied demo's emotion-specific motion accompanies the animated eye/body frames. Offscreen/background views and Reduce Motion stop playback. Inbox and private-chat header avatars breathe between blinks. | Persisted real Eve `triste`, SQL tone/lease/access assertions, and native rendered-window tests. The mounted-window regression caught the visibility gate that asset-only checks missed; source resolution is checked against native display density. The selected physical iPhone test confirms exact image bounds and changing rendered pixels; the UIKit intrinsic-size overflow was reproduced before repair. |
| Pal activity | In every room, the reserved composer lane shows animated Pal is typing only after Pal explicitly chooses a public reply and finishes its other tools. Queued work and silent observations stay quiet; completion or a 20-second expiry ends typing. | Native stale-state and fixed-height checks; SQL current-attempt, membership, silence and 20-second expiry assertions; hosted selected-reply activity check. |
| Reply and react | Native long-press reaction palette, Reply and Copy. Text URLs are tappable. | Native render and hosted reply/reaction assertions. |
| First entry and realtime | Unknown history shows a loading state; only an authoritative empty snapshot shows No messages yet. Overlapping GETs share one request, successful writes invalidate only affected reads, and refresh failures retain content with inline retry. Unchanged background snapshots do not publish new UI state; transcript ordering and date grouping are cached by complete source values, with one stable lazy child per message. The inbox prefetches messages, member names, group state and member photos for at most two groups at once. Reopened chats reuse account-scoped memory; avatar images share a bounded decoded cache that survives signed URL rotation, and media loading keeps a fixed frame; authenticated current-group Realtime inserts validated text immediately and coalesces parallel authorized enrichment reads, with polling recovery. | Native unknown/empty, stale snapshot, logout/prune and actual WebSocket tests; hosted three-client member/outsider CDC verification. |
| Failed delivery | No sending indicator. Accepted responses enter the cache before the outbox clears; stable client identity keeps one bubble through delivery. Failed text/media retain the original reply and file for retry. | Hosted idempotency and native stale-snapshot/outbox tests; the user confirmed the bubble no longer disappears. |
| Photos and audio | Plus opens Photos, Camera or Audio; review/remove a draft before sending. Private signed media is shared with group members. | Hosted and native actual JPEG/AVFoundation AAC uploads/downloads, exact retry, replies, invalid-file rejection and outsider access denial. Uppercase iOS UUID URLs are exercised. Hardware camera/microphone checks remain manual. |
| Share a reel | Share extension selects a group and submits through the authenticated message API; pasting uses the same ingestion. | Extension builds/session tests; pasted real reel live. System share gesture remains a manual check. |
| Inspect a place | Pal describes results in text with the original link. Resolved places remain saved for chat and planning; uncertain branches require a conversational correction. | Real supplied reel: Tur, five dishes and timestamp evidence; Apple Maps match. |
| Unclear/inaccessible source | Inspection preserves the source and ends with one short factual reply after it resolves or fails. Pending inspection stays quiet; members clarify uncertain branches in chat. | Schema/security tests and correction flow review. Private-video provider behavior varies. |
| Multiple places | Pal lists useful candidates in text; validated resolved records remain in the group’s saved collection. | Validated multi-candidate extraction and saved-place records; actual multi-place video remains a manual provider check. |
| Collection and duplicates | Ask Pal for saved places or Hangout recommendations. One persisted place keeps its source contributors; no Map screen is exposed in the demo. | Hosted dedup, SQL and native state/render. |
| Preferences and context | Pal quietly reads group history and remembers explicit statements about the speaker. Members correct it through chat; no memory editor. | Real Eve ordinary-message preference capture with exact speaker/source and zero unsolicited reply; SQL ownership assertions. |
| Availability | Members state their times naturally. Pal remembers exact speaker/source and applicable dates; dated availability expires, unanswered remains unknown. | Source-grounded capture and expiry assertions; missing responses stay unknown and an explicit empty response means none of the proposed slots work. |
| Choose a place | Pal offers a horizontal inspiration card with saved-place details or activity ideas. Tiles are read-only; members answer naturally in chat. Anything works is a preference, never attendance. | Source-grounded member response checks and persisted same-group option references. |
| Confirm and RSVP | An explicit member message can confirm a current future draft. Confirmation automatically posts RSVP invitations tagging current members, in batches of at most eight mentions. Attendance stays a separate own Yes/Maybe/No response. | Conservative intent tests and SQL current-version/source/lease/idempotency assertions; real member RSVP and Google sync verified. |
| Reserve | Research verifies a booking link; a member opens it and records a completed booking. Drafts do not imply booked tables. | Real official booking-page verification plus scoped-tool tests. No reservation submitted. |
| Quick actions | Floating emoji glass controls above the composer ask Pal for Plans, Schedule or Hangout in groups, and Summary or Plans across current memberships in private chat. They preserve an unfinished draft. | Native builds and shared message validation. |
| Member details | Tap a member to open a group-scoped AI summary, explicitly shared availability and upcoming attending plans. Unknown schedules remain unknown; private calendar details are excluded. | Hosted real AI summary, source citations and membership denial; native decoding/cache tests and physical mounted review. |
| Mentions and replies | Type @ to choose Pal or a group member. Reply from a message menu; quoted text survives outside the current history window. A reply to Pal is addressed to Pal without a required @. | Native decoding/composer tests; same-group mention/reply guards and hosted conversation acceptance. |
| Multiple Pal replies | Pal can deliberately send up to three ordered short messages, each retaining its own emotion and optional quote. Ordinary paragraphs remain one message. | Output bounds, SQL atomicity/replay tests, hosted Eve completion. |
| RSVP invitation | A compact plan card shows venue, date and current attendance, with Yes, Maybe, No after confirmation and a detail destination for the rest. Automatic invitations tag every current member; split invitation bubbles produce one push per recipient and plan version. Each member owns their response; the same card reflects edits or cancellation. | Native eligibility/response tests, SQL member permissions, hosted edit/cancel/retry checks. |
| Plan details | The chat card keeps the next action visible. Full details put venue and date first, then attendance and RSVP; booking information is secondary, and edit/cancel stay in the native action menu. | Native build plus confirmed/draft/past model checks; physical mounted-screen review passed. |
| Group calendar | Push Calendar, swipe between months or use accessible previous/next controls, choose a date and review the agenda; native back and swipe-back. | Native calendar render/model tests; gesture remains a device check. |
| Google Calendar | Connect once; create a separate Pal calendar; sync only confirmed plans where that member said Yes. | Real consent, exactly one live Google event, and an edited plan updating the same copy despite retries. |
| Apple Calendar | Open Apple's native editor, review and save a manual copy. Pal does not read personal events. | Native editor/date/receipt checks; physical save requires a member action. |
| Follow-ups | Responded members are excluded; remaining reminders stop once resolved. Quiet hours apply to nonurgent pushes. | SQL recipient/deadline assertions. |
| Attendance reminders | Server schedules future 24h/2h reminders for Yes attendees; pushes open the relevant record. | SQL lifecycle plus a physical closed-app reminder/tap check. |
| Changes and cancellation | Persisted plan details and RSVP cards update; material time changes clear RSVPs and replace reminders/calendar copies. | Hosted lifecycle assertions and real Google edit/retry/cancellation cleanup. |
| Direct reminder | Ask Pal in chat; Pal confirms the saved purpose and local time in text. Scheduling persists on the server. | Hosted server reminder and physical closed-app APNs/tap verification. |
| Notification control | Explicit Enable requests iOS permission. Background registration failures appear quietly in Profile and do not interrupt navigation; successful registrations are deduplicated within the signed-in session. Foreground chat updates do not show banners or play sounds. Same-turn Pal bubbles coalesce; reading cancels already-read queued chat pushes while preserving reminders. | Physical permission, device registration and APNs delivery; native failure-presentation checks. |
| Demo scenarios | Two dedicated Demo rooms reuse three fictional photo profiles. Their normal composer prefills drive sequential cast and short mock Pal replies; Dinner uses guarded real plan/RSVP operations; restart clears only that registered room. Existing other rooms and login/profile/device/Calendar connections remain. Three verified fixture-only test rooms were backed up privately before cleanup. | Reviewed manifest, real venue resolution, guarded seed and private completion receipt. Mock dialogue never implies an actual reservation. |
| Group details | Members and invitations only; agent settings and manual memory/poll creation are hidden. | Native flow review; existing backend guards remain in place. |
| Share location | Explicit Share location in a shared group’s + menu requests When In Use permission. Only selected groups receive foreground updates, throttled to one minute or 200 metres, with one-hour expiry. Stop removes the point and keeps failed removal retryable; the private Pal room never shares location. | Input/expiry/group isolation SQL and native lifecycle checks; a real GPS permission/location walk remains manual. |
| Accessibility | Native text/controls, meaningful action labels, Dynamic Type layouts, light/dark mode and Reduce Transparency fallback. | Native accessible dark rendering and builds. Light/dark native rendering and accessible RSVP layouts were reviewed on the iPhone. VoiceOver narration remains a manual check. |

Deferred features remain automatic booking, two-way calendar sync, games, image generation and a personal feed. Google's test-mode OAuth warning is expected; its refresh credentials can expire after seven days. The installed Debug app uses sandbox APNs; TestFlight needs production APNs credentials.

Performance review followed Apple’s [lazy-stack guidance](https://developer.apple.com/documentation/swiftui/creating-performant-scrollable-stacks), [ForEach identity rules](https://developer.apple.com/documentation/swiftui/foreach), and [performance-analysis workflow](https://developer.apple.com/documentation/swiftui/performance-analysis). A 20-second physical Time Profiler baseline was captured while the user scrolled; this Debug trace does not establish an FPS guarantee. Native regressions cover source-cache invalidation, optimistic reconciliation, full snapshot equality, and mounted animated avatars.

Hosted API measurements and the endpoint audit are recorded in [API performance](api-performance.md). Agent turns start with a verified, bounded 32 KB snapshot instead of rereading the same group immediately; every mutation still checks the current lease and group scope.

Pal actively addresses untagged planning ideas, unresolved questions and useful next steps while leaving resolved member exchanges alone. Group bursts wait three seconds, then the agent decides; a tag or reply to Pal skips that wait. The ask_group_question tool returns a validated question with two to four short suggested answers. Taps send ordinary member replies quoting the actual delivered question, while typing and the normal Reply menu remain available. It does not pause Eve awaiting interactive input.
